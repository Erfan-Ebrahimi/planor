# RTL and Persian adaptation

Planor's document and core interface should use Persian and RTL. The source HTML starts with `lang="en"` and lacks a root direction override. Its localization and date-language changes operate independently of layout direction. Apply semantic order at the document/container level and logical spacing at the component level. Source: `client/public/index.html`, `client/src/i18n.js`, `client/src/components/Core/Core.jsx`.

## Bidi content, font and input

- Isolate user-provided spans such as card and list names, mention display names and quoted historical names so adjacent punctuation and metadata stay in order. Apply explicit LTR isolation to technical values such as email, URLs, file extensions, machine IDs, hex colors and optional ASCII time inputs. Preserve full raw URL and attachment values when copying. Show display name and file extension separately where practical.
- Handle Persian `ی`/`ک` and Arabic equivalents, ZWNJ, Unicode combining forms, and Persian/Arabic/ASCII numeral input. Confirm matching policy for sidebar, board search, mention suggestions and labels. The current source typically lowercases and compares strings directly. Respect composition events before Enter/Escape submit or mention selection. Inspect wrapping, overflow and caret coordinates with phrases such as «بازبینی راهنمای پرداخت با @نیلوفر رستگار» and attachments named «گزارش آبان.pdf».
- The configured Museo Sans Cyrillic WOFF2 and paired TTF files were inspected through their character maps. All five weights in both styles lack the sampled Arabic/Persian glyphs `ا پ چ ژ ک گ ی` and Persian digits `۰ ۹`. Browser fallback choice is **Unverified**. Use a licensed Persian-capable UI family with tested shaping, line height, numeral forms and weights. Test font metrics before choosing card clamping or fixed line heights. Provide a separate code/identifier stack only where needed.
- Use the Jalali display and picker mapping in [Dates](dates.md). Group numbers, date separators and neutral icons into one isolated unit. Keep a screen reader-friendly label for overdue and calendar status, since the source often relies on color and hover alone.
